# Проверенная конфигурация Play Integrity

На установленной Infinity X 4.1 / Android 17 для `dash` получены **Basic, Device и Strong**; Play Маркет показывает **«Устройство сертифицировано»**. Повторная проверка после сброса только Play Маркета дала тот же результат. Это наблюдение после настройки системы, а не обещание вечного прохождения проверок или результат установки одного ZIP.

Публичный итог: [validation/2026-11-01-integrity.json](../validation/2026-11-01-integrity.json). Исходный ZIP и его хеш не менялись. Для этого исправления пересборка и перепрошивка не выполнялись.

## Что сохранено

В `device/xiaomi/dash/configs/integrity/` находятся:

- `pif.json`: проверенный профиль Pixel 6a `bluejay_beta`, `spoofProvider=false` для встроенного TrickyStore;
- `gameprops.json`: `PRODUCT_FOR_ATTESTATION=dash_ru` для GMS и Play Маркета;
- `policy.json`: источник keybox, разрешённый SHA-256, отпечатки корневых сертификатов Google, модель/SDK, список целевых пакетов и хеши публичных JSON.

`dash_ru` подтверждён для телефона владельца. Другой региональный вариант устройства требует отдельной проверки заводской идентичности.

В будущей сборке эти три публичных JSON копируются в `/system_ext/etc/infinity/integrity/`. **Они не применяются автоматически при загрузке.** Для восстановления используется явная команда ниже. Существующий установленный ZIP не содержит этих новых файлов.

Приватный keybox XML не включается в Git, прошивку, логи или публичные артефакты. Ключи подписи нашей прошивки также хранятся отдельно: подпись APK/OTA и ключ аттестации — разные вещи.

## Проверить или восстановить

Нужны Python 3, OpenSSL 3 и ADB. Запускать из корня этого репозитория. Сначала проверить актуальный файл из официального источника EvoX:

```sh
python3 tools/integrity_config.py inspect
```

Команда не обращается к телефону. Она загружает XML по HTTPS, проверяет структуру, размер, соответствие приватного ключа сертификату, цепочку подписей, доверенный корень Google, срок действия и текущий список отзывов Google. В выводе только публичная сводка. Код завершения `0` означает проверенный файл с разрешённым хешем; `2` — корректный файл с новым хешем, требующий рассмотрения; `1` — проверка не пройдена.

При необходимости можно проверить локальный XML **вне Git**:

```sh
python3 tools/integrity_config.py inspect --keybox-file /private/path/keybox.xml
```

Для явного восстановления на проверенном `dash` / `2602BPC18G`, SDK 37:

```sh
python3 tools/integrity_config.py apply --serial ADB_SERIAL --factory-product dash_ru
```

Перед записью инструмент повторяет проверки keybox, сверяет модель/SDK и хеши публичных профилей. Меняет только пять настроек встроенных PIF/TrickyStore; целевые пакеты — GMS, Play Маркет и GSF. Сохраняет предыдущие значения в `~/.local/share/infinity-dash/integrity/settings-before-*.json` с правами `0600`, вне Git. Не публиковать этот файл: он может содержать прежний приватный keybox. При ошибке записи инструмент пытается вернуть предыдущие значения и проверяет результат; при разрыве ADB откат может потребовать повторного подключения и приватной резервной копии.

После успешной записи принудительно останавливаются GMS и Play Маркет для перечитывания настроек. Root, очистка данных, перезагрузка и запись разделов не используются. Выполнить свежий тест Integrity и проверить сертификацию в настройках Play Маркета. Если Маркет показывает старый статус, сначала исключить кэширование; очистка его данных не входит в инструмент и не заменяет проверку результата.

## Если вернуться через неделю

Сертификат проверенного keybox истекает **6 ноября 2026, 07:53:17 UTC**. Его могут отозвать раньше; доступность замены не гарантируется. Это срок сертификата, а не прошивки. В [коде EvoX](https://github.com/Evolution-X/packages_apps_Evolver/blob/cnb/src/org/evolution/settings/fragments/miscellaneous/TrickyStore.kt) также предусмотрены проверки отзыва/истечения и замена keybox.

1. Проверить локальный commit и изменения: `git status --short`, затем тесты и `python3 tools/preflight.py`.
2. Запустить `inspect`. Если сервер отдаёт другой файл, `apply` остановится из-за SHA-256, даже если цепочка корректна.
3. Рассмотреть публичную сводку нового файла; проверить источник, сроки и отсутствие отзывов. После проверки обновить разрешённый SHA-256 и срок в `policy.json`, затем соответствующий device patch и сохранить проверенное изменение отдельным commit.
4. Выполнить `apply` и новый тест на телефоне. Пересобирать Android ради замены keybox не нужно.

Фоновой загрузки или автоматического принятия нового хеша в этом инструменте нет. Если подходящей замены нет, прохождение всех уровней обещать нельзя. Проверки хешей выявляют отклонение от доверенной локальной копии; они не дают гарантии при одновременной компрометации сервера и самой локальной копии. Успешный Integrity также не означает, что загрузчик физически заблокирован.
