# Подготовка owner-only автоматизации

Автоматизация ещё не подключена: Actions выключены, self-hosted runner отсутствует. `run_policy.py` — проверяемый компонент будущего ограниченного интерфейса запуска, а не готовая система авторизации.

Он принимает только ручной запуск с разрешёнными repository ID, owner ID, workflow path, веткой main и заранее одобренным commit. Проверяется также инициатор повторного запуска и факт старта единственного нужного job после environment gate.

При интеграции данные должны запрашиваться самим сервером через GitHub API, а не приниматься на веру от SSH-клиента. Jobs запрашиваются для текущего run_attempt. Необходимы отдельный replay guard для пары run_id/run_attempt, ограниченный канал без административного SSH-ключа и проверка результатов перед prerelease-публикацией. Одного вызова этой функции недостаточно для безопасного подключения VM.

`protocol.py` разбирает только ограниченные команды start/status/fetch и не исполняет текст запроса. `ota_integrity.py` проверяет контейнер ZIP, целевое устройство и хеши/размеры payload. Последний намеренно не считается полной проверкой Android payload, AVB-подписей или работоспособности прошивки; перед публикацией нужны дополнительные проверки образов.

Контейнер и его SHA-256 читаются через один открытый дескриптор; ссылки и замена файла во время проверки отклоняются. Перед будущей публикацией готовые файлы нужно перенести в staging, недоступный сборщику для записи, проверить там и отправлять именно эти байты. Проверка текущего файла не защищает от его последующего изменения в writable `out/`.

`state.py` резервирует пару run_id/run_attempt без перезаписи и не создаёт новое задание при повторе того же запроса. Записи сбрасываются на диск до продолжения; повреждённая запись блокирует повторный запуск до разбора, а не удаляется автоматически. Каталог состояния должен принадлежать root и быть недоступным для записи сборщику.

`github_api.py` получает сведения о запуске и jobs конкретной попытки с `api.github.com`, сверяет их с запросом и применяет `run_policy.py`. Сетевой сбой, неполный ответ или несовпадение не разрешают запуск. Соединение использует системную проверку TLS; учётные данные администратора для чтения публичного репозитория не нужны.
